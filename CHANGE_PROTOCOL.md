# Протокол изменений

1. Прочитать README, PROJECT_CONTEXT, ARCHITECTURE, MODULES, этот файл и журнал.
   Проверить `git status`, текущую ветку, commit, remotes. Не затирать чужие изменения.
2. Если origin настроен и доступен, получить обновления через fetch; интегрировать
   только после проверки локальной работы. Без доступа сообщить о работе со снимком.
3. Указать модуль, задачу, затронутые общие контракты и зависимые модули.
   Перед изменением схемы описать миграцию; перед новым API — потребителей.
4. Сделать ограниченное изменение в одной кодовой базе. Не вести независимые
   расходящиеся копии в разных чатах. Использовать отдельную ветку для задачи.
5. Проверить сборку и затронутые сценарии. Для финансовой логики проверять
   точность, округление, переводы и согласованность балансов; для схемы — миграции.
6. Обновить PROJECT_CONTEXT, ARCHITECTURE/MODULES при необходимости,
   CHANGELOG и VALIDATION. Отдельно указать, что не проверялось.
7. Просмотреть diff, сохранить commit. Push только в подтверждённый собственный
   remote с правом записи; PR использовать для проверки и объединения изменений.
8. Завершить передачей: commit/ветка, изменённые файлы, контракты, проверки,
   затронутые модули и следующий шаг. В другом чате снова читать актуальные файлы.

Обновление GitHub не рассылает сообщения в другие чаты и не обновляет ранее
загруженные файлы ChatGPT. Снимки проекта нужно перезагружать вручную.
